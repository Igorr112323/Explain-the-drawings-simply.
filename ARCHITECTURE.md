# Архитектура IkGuide

Главная мысль: **центр продукта — детерминированное ядро и настоящий PDF-файл**, а не интерфейс.
Один и тот же React-бандл работает и в браузере, и внутри `.exe`; распознавание — единственный
локальный Python-сервис, который отдаёт данные в формате документа инструкции. Продукт работает
только с 2D-чертежами: ни 3D-моделей, ни CAD-ядра в конвейере нет.

```
файл (JPG/JPEG/PNG/WEBP/PDF)
        │
        └── /v1/recognize ──┐   (vision-api: OpenCV, PyMuPDF, RapidOCR)
                            ▼
                 @ikguide/builder  ──▶  IkGuideDocument (Zod, schemaVersion 1.0)
                            │                    │
              @ikguide/gost-translator           │
              (расшифровка обозначений)          ▼
                                      @ikguide/pdf-exporter
                                      план листов A4 → jsPDF + svg2pdf
                                                 │
                                                 ▼
                                   <Название>_<Шифр>_инструкция.pdf
```

---

## 1. Принципы

1. **Детерминизм вместо генерации.** ГОСТ-переводы считаются по таблицам и формулам: один и тот же шифр
   всегда даёт один и тот же ответ. Никаких LLM в конвейере нет.
2. **Anti-hallucination как свойство формата.** У каждого обозначения есть `confidence` и
   `confirmedByHuman`; порог `0.95` живёт в `@ikguide/schema`. Всё, что ниже, попадает в документ как
   вопрос к человеку и печатается в PDF с пометкой «проверить по чертежу».
3. **Один UI, две оболочки.** `apps/studio-web` собирается с относительным `base`: тот же `dist`
   загружает Tauri. Оболочка добавляет только нативное «Сохранить как…».
4. **Один источник вёрстки.** Предпросмотр в браузере и файл рисуются из одного объекта
   `InstructionPlan` — совпадение гарантировано конструкцией, а не дисциплиной.
5. **Результат — файл.** Продукт не хранит архив инструкций: скачали `.pdf` — задача закрыта.

## 2. Пакеты

### `packages/ikguide-schema`

Zod-схема документа: `metadata` (название, шифр, материал, заготовка, масса, ревизия), `bom`,
`tools`, `steps` (текст, иллюстрация, `antiError`, `criticalChecks`, `drawingRefs`, `cropPercent` —
зона листа под шаг, `svgDiagram`), `xrayAnnotations`, `qcChecklist`.

Схема — единственный контракт между распознаванием, UI и экспортом: всё, что не проходит
`safeParse`, не доходит до PDF. Координаты шага (`cropPercent`) — проценты листа 0…100, поэтому
обрезка одинаково работает и для фото, и для PDF.

### `packages/gost-translator`

`translateEngineeringNotation(raw) → TranslationResult`: резьба (`М8-7H`, `М10×1,25`), посадки
(`Ø20 H7`, `Ø32 H7/k6`), шероховатость (`Ra 1.6`), сварные швы (`Т1-К5`), фаски, радиусы, группы
отверстий, линейные размеры. Возвращает `standard`, `explanation` (человеческим языком),
`workerAdvice` и рекомендуемый инструмент.

### `packages/ikguide-builder`

* `buildGuideFromVision(response, options)` — кандидаты распознавания → шаги по стадиям обработки,
  инструмент под каждое обозначение, контрольные замеры, чек-лист, предупреждения.
* Таблица позиций (`bomRows`) превращается в шаги комплектности сразу после подготовки, а подписи
  видов (`views`: «Спереди», «Сбоку», «Сверху», «Изометрия») — в шаги-ориентиры; строки таблицы
  дополнительно попадают в `bom` с количеством и номером позиции.
* Каждый шаг получает `cropPercent`: объединение областей своих обозначений с запасом, а если своих
  нет — зону ближайшего вида. Дальше UI режет лист ровно по этой зоне (`lib/pipeline.ts`).

### `packages/pdf-exporter`

Три слоя, каждый со своими тестами:

| Файл | Роль |
| --- | --- |
| `text.ts` | ширины глифов из реальных метрик DejaVu, переносы строк, высота блоков, эллипсис |
| `plan.ts` | модель листов A4: титул, шпаргалка, шаги (2×A4 или один крупный), чек-лист, колонтитулы |
| `render.ts` | jsPDF + svg2pdf, вшитые шрифты, `renderInstructionPdf() → Uint8Array` |

Дизайн «IKEA 2.0»: поля 16 мм, три цвета (`#1D1D1F` контуры, `#007AFF` активное, `#FF3B30` критичное),
номера шагов 26 pt, схемы 92×60 мм, подвал `Стр. 2 из 5`.

## 3. Приложения

### `apps/studio-web`

| Слой | Файлы | Ответственность |
| --- | --- | --- |
| Конвейер | `lib/pipeline.ts` | классификация файла, вызовы сервисов, `PipelineError` с подсказкой |
| Правки | `lib/fixes.ts` | чистые функции документа: размер, текст шага, «Осторожно!», ракурс, расшифровка |
| Схемы | `lib/illustrations.ts` | документ → SVG для каждого шага (арт-реестр 2D) |
| Фрагменты | `lib/sheetFragment.ts` | для загруженного скана: вырезает лист вокруг `drawingRefs` шага (canvas, JPEG) |
| PDF | `lib/pdfExport.ts`, `lib/nativeExport.ts` | план → байты → скачивание или нативное сохранение; jsPDF подгружается по кнопке |
| Состояние | `state/pipeline.ts` | `upload → working → review/error`, прогресс, занятость PDF, история правок для «Отменить» |
| Тема | `lib/theme.ts` | светлая/тёмная тема цеха: один атрибут `data-theme` на `<html>`, выбор в localStorage |
| Движок | `lib/engine.ts`, `lib/nativeOpen.ts` | пинг `/health` локального движка; нативный проводник Windows в `.exe` |
| UI | `components/*` | холст, пять капсул, поповеры, листы A4 |
| Примитивы | `components/Pill.tsx`, `components/icons.tsx` | капсулы, круглые кнопки, поповер (Esc + клик мимо), тонкоконтурные иконки |

**Холст (`App.tsx`).** Весь экран — белое поле с точечной сеткой (`radial-gradient`, шаг 22 px). На нём
ровно пять парящих капсул: назад (слева сверху), «отмена / экспорт PDF / меню» (справа сверху), примеры
(слева снизу), «текст / рентген ГОСТ / загрузка» (по центру снизу) и «пометка» (справа снизу). Поповер
растёт из своей капсулы, закрывается по `Esc` и по клику мимо; постоянных панелей и сайдбаров нет.

**Адреса блоков.** `plan.ts` помечает часть блоков `target`
(`title`, `step-title`, `step-text`, `step-anti`, `step-illustration`, `notation`). Живой холст превращает
такой блок в кнопку, поэтому клик по названию или абзацу прямо на листе A4 открывает правку ровно того
поля документа. В PDF адреса не попадают — jsPDF их не рисует, а тест проверяет, что колонтитулы и
контрольные замеры адресов не получили.

Предпросмотр (`components/PagePreview.tsx`) рисует блоки плана в реальных миллиметрах на листе
210×297 мм и масштабирует целиком через `transform` — поэтому переносы строк и отступы совпадают с PDF.
Масштаб стола — отдельная, максимально незаметная мини-пилюля `− 100% +` в правом нижнем углу:
колесо и пинч (в том числе без ⌘/Ctrl) дают 40…250 %, `Ctrl/Cmd +`, `−`, `0` работают как в браузере,
клик по проценту сбрасывает на 100 % и центрирует листы. При масштабе > 100 % фон можно тащить
(ПКМ, СКМ, `Пробел + drag` или ЛКМ по пустому месту), а клики в редактируемые поля и прокрутка
поповеров не перехватываются. Математика зума вынесена в `lib/zoom.ts` и покрыта тестами.

### `apps/desktop-tauri`

Тонкая оболочка: то же окно (1320×840, фон `#FBFBFD`), плюс `tauri-plugin-dialog` и `tauri-plugin-fs`.
Кнопка `↑` открывает системный диалог «Сохранить как…» и пишет байты выбранным путём; если плагины
недоступны — тихий откат к скачиванию. Скрепка открывает проводник Windows с фильтром 2D-чертежей.
Команда печати удалена: файл важнее print job.

В `setup` шелл ищет `engine\ikguide-vision.exe` рядом с `.exe` (установщик кладёт его ресурсами) и:
1. пингует `GET /health` на `127.0.0.1:8000` (и `8001` как запасной) — если движок уже запущен
   вручную, второй экземпляр не поднимается;
2. запускает sidecar в фоновом потоке с `CREATE_NO_WINDOW`, `stdin/stdout/stderr = null` — без
   чёрного окна консоли и без мусора в консоли приложения;
3. ждёт порт до 30 с (`wait_for_health`) — окно при этом уже открыто;
4. при `RunEvent::Exit` глушит всё дерево процессов (`taskkill /PID <pid> /T /F`), потому что
   PyInstaller onefile создаёт дочерний процесс.

Нет файла — приложение работает, а команда `engine_status` и меню «•••» честно сообщают, что фото и
сканы не распознаются, а векторные PDF работают.

Установщик — NSIS с собственным шаблоном `src-tauri/nsis/installer.nsi` (на базе официального шаблона
Tauri v2, вся логика WebView2/ярлыков/удаления сохранена) и своими картинками мастера
(`nsis-sidebar.bmp` 164×314, `nsis-header.bmp` 150×57, 24-bit BMP). Оформление: белый фон,
`XPStyle on`, `ManifestDPIAware`, `MUI_BGCOLOR "FFFFFF"`, `MUI_TEXTCOLOR "1C1C1E"`, свои
`SetCtlColors` на Welcome/Directory/InstFiles/Finish и русские заголовки. Поток мастера — четыре шага:
приветствие → папка установки → установка → «Готово». Сборка только `nsis`: WiX/MSI падает на
кириллице в codepage 1252.

## 4. Сервисы

### `services/vision-api` (порт 8000)

* `POST /v1/recognize` — до 8 листов: рамка, перспектива, тени, штамп ГОСТ 2.104, обозначения с
  координатами и уверенностью. Векторный PDF читается из текстового слоя, фото/скан — через OCR.
  Дополнительно отдаёт `bomRows` (строки таблицы «ПОЗИЦИЯ / ОБОЗНАЧЕНИЕ / НАИМЕНОВАНИЕ / КОЛ-ВО») и
  `views` (подписи видов); разбор строк живёт в `app/tables.py`.
* `POST /v1/recognize/roi` — перечитать конкретную область листа (ручная правка пропущенного размера).
* `GET /health` — версия, доступный OCR-движок, порог уверенности.
* **Мелкий лист.** Если ширина листа меньше 1400 px (фото старой копии, скриншот), он увеличивается
  в 2–3 раза `cv2.INTER_CUBIC` с аккуратным unsharp (`preprocessing.upscale_for_ocr`), а раскладка и
  координаты пересчитываются тем же коэффициентом (`Layout.scaled`) — проценты остаются прежними.
  В ответе это честно видно как `pages[].upscale` и предупреждение, а не как «магия».
* Никаких файлов на диске, никакой раздачи студии, никаких сетевых адресов: только распознавание.

Сервис слушает `127.0.0.1:8000`; в браузере UI обращается к относительному `/v1/...`, и Vite
проксирует его на 8000 (`vite.config.ts`). В упакованном `.exe` адрес берётся из
`lib/runtimeConfig.ts` (тот же порт на loopback).

## 5. Потоки данных

### 2D: скан или PDF

```
файл → recognizeSheets → VisionRecognizeResponse (candidates, bomRows, views, upscale)
     → buildGuideFromVision → IkGuideDocument (+ warnings, skipped)
        шаги этапов + шаги комплектности по таблице позиций + шаги-ориентиры по видам,
        у каждого шага cropPercent
     → fragmentsFor: обрезка листа по cropPercent, иначе вокруг drawingRefs (canvas, JPEG)
     → UI: жёлтые вопросы по confidence < 0.95, пины на листе, расшифровки ГОСТ
     → buildInstructionPlan + buildIllustrations → renderInstructionPdf → .pdf
```

Правка размера (`applyDimensionFix`) — это замена токена по всему документу: аннотация, текст шагов,
критерии приёмки, чек-лист, размеры в спецификации и инструменте.

## 6. PDF: почему он настоящий

* **Клиент.** jsPDF и svg2pdf работают в браузере: демо и офлайн-режим дают файл без сервера.
* **Шрифт.** Подмножества DejaVu Sans (regular + bold) лежат base64 в
  `packages/pdf-exporter/src/fonts/dejavu.ts`, метрики — в `metrics.ts` (в единицах шрифта,
  `unitsPerEm = 2048`). Пересобираются скриптом `scripts/build-pdf-fonts.py`.
* **Кириллица.** В PDF есть `/ToUnicode` CMap и `/FontFile2` — текст извлекается и копируется,
  `Ø ± ° × №` рисуются настоящими глифами (`⌀`/`∅` нормализуются в `Ø`).
* **Вектор.** `PlanSvg` передаётся в svg2pdf: в демо растровых XObject нет вовсе, и это проверяется
  тестом (`/Subtype /Image` отсутствует).
* **Фрагменты скана.** Если инструкция собрана из фото/PDF, шаг получает `PlanImage` — обрезку листа
  вокруг его обозначений (`fragmentBox` считает границы и пропорции, `cropSheet` уменьшает до 720 px).
  Это единственный растр в файле, и он — исходный чертёж пользователя, а не сгенерированная графика;
  тест проверяет, что такая страница действительно содержит `/Subtype /Image`.
* **Совпадение с экраном.** `text.ts` меряет строки ширинами глифов, `plan.ts` переносит их заранее,
  а предпросмотр рендерит те же строки теми же блоками.

## 8. Что удалено и почему

Чтобы продукт остался однозадачным, из репозитория убраны: QR-мост и deep-links (`?g=`, `?guide=`),
сканирующее приложение Capacitor (`.apk`), цеховой сервер публикаций (`/v1/guides`, `/v1/network-info`),
экран рабочего с 7 шагами, Web Speech, «умная камера» (`getUserMedia`), IndexedDB-библиотека офлайна,
экспорт `.ikguide.json`/`.html`. Осталась цепочка «файл → документ → PDF» и её ядро — теперь на
собственном белом холсте с парящими капсулами (тот самый Freeform-принцип, но без чужой библиотеки).

## 9. Вес бандла

Первый экран не тянет ни графику, ни рендер: главный чанк ≈ 0,93 МБ (300 КБ gzip), а `render`
(jsPDF + svg2pdf + шрифты, 243 КБ) подгружается по требованию — только когда человек нажал
«Скачать PDF-инструкцию».

## 10. Ограничения

* Rust в песочнице нет (`rustc`/`cargo` отсутствуют): `.exe` собирается на Windows/в CI
  (workflow «Build Windows .exe»), здесь проверяются конфиги (`npm run check:native`, 145 проверок) и бандл.
* Упаковка движка через PyInstaller — отдельная джоба `continue-on-error: true`: даже если она
  споткнётся на новой зависимости, UI-установщик и portable `.exe` всё равно соберутся.
* Вход — только 2D: `.jpg/.jpeg/.png/.webp/.pdf`. 3D-модели не принимаются ни в одной точке конвейера.
* OCR зависит от качества скана: неуверенные значения не прячутся, а превращаются в жёлтый вопрос.
* Таблица позиций читается и без шапки (по структуре строки «5 Ручка жаровни 2»), но подписи видов и
  строки спецификации, напечатанные слишком мелко, распознаются хуже — потому мелкие листы и
  увеличиваются перед OCR.
* PDF не является чертежом: это инструкция для человека, размеры в ней — справочные.
