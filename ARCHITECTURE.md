# Архитектура IkGuide

Документ фиксирует решения этапа 1 и дорожную карту этапов 2–4. Главная мысль: **ядро продукта не зависит
от LLM и от платформы**. Фронтенд один, оболочки разные, распознавание — отдельный сервис, который обязан
отдавать данные в тот же формат `.ikguide.json`, что и ручной редактор.

---

## 1. Принципы

1. **Детерминизм вместо генерации.** Все переводы ГОСТ/ЕСКД считаются по таблицам и формулам. Один и тот же
   шифр всегда даёт один и тот же ответ — это проверяется тестами и не «плывёт» между версиями.
2. **Anti-hallucination как свойство формата, а не интерфейса.** У каждого обозначения есть `confidence` и
   `confirmedByHuman`. Порог `0.95` живёт в `@ikguide/schema`, поэтому ни OCR, ни будущий LLM-слой не могут
   обойти подтверждение человеком.
3. **Один UI — две оболочки.** `apps/studio-web` собирается как SPA с относительным `base`, поэтому его без
   изменений загружают Tauri (Windows `.exe`) и Capacitor (Android `.apk`).
4. **Source-first монорепо.** Пакеты экспортируют TypeScript из `src`, Vite транспилирует их на лету, а
   `tsc -p tsconfig.build.json` дополнительно выпускает `dist/` с `.d.ts` для будущих потребителей.
5. **Русский язык — только в UI и текстах.** Идентификаторы, типы, имена файлов, комментарии — английские.

## 2. Карта модулей

```
                 ┌──────────────────────────────────────────────┐
                 │            apps/studio-web (React)          │
                 │  worker (6 экранов) │ engineer (Freeform)   │
                 │  print A4 │ QR │ speech ru-RU │ upload       │
                 └───────────────┬──────────────┬──────────────┘
                                 │              │
             @ikguide/schema ────┘              └──── @ikguide/gost-translator
             (Zod-документ,             (таблицы ГОСТ + детерминированные
              порог 0.95, IO,            парсеры резьб, посадок,
              moveStep, статистика)       шероховатости, швов, фасок)
                                 │
                                 ▼
                       .ikguide.json (schemaVersion "1.0")
                                 ▲
        этап 2: OCR/OpenCV сервис│этап 3: STEP/3D конвейер
        (Python FastAPI)         │(Python + OCP → glTF)
```

### Ключевые типы

| Тип | Где | Роль |
| --- | --- | --- |
| `IkGuideDocument` | `packages/ikguide-schema/src/schema.ts` | Единый документ инструкции |
| `XrayAnnotation` | там же | Обозначение на листе: `raw`, `kind`, `xPercent/yPercent`, `confidence`, `confirmedByHuman`, `ambiguousOptions`, `resolvedValue` |
| `TranslationResult` | `packages/gost-translator/src/types.ts` | Дискриминированное объединение ответов переводчика |
| `StepIllustration` | схема | `illustrationId` + слои подсветки `highlight[]` + `arrows[]` — схема шага хранится как данные, а не как картинка |

Слой подсветки (`shapeId → accent | danger | done`) — это и есть «2D-слои» из брифа: один и тот же SVG
перекрашивается под текущий шаг, поэтому не нужно рисовать отдельную иллюстрацию на каждое действие.

## 3. Поток данных (целевой)

1. Инженер фотографирует или импортирует чертёж (PDF/PNG/JPEG).
2. **Этап 2:** OCR/векторный анализ возвращает список обозначений с координатами и `confidence`.
3. Схема валидирует документ; всё с `confidence < 0.95` уходит на экран «Быстрая проверка».
4. Инженер правит текст шагов и анти-ошибки на холсте, добавляет подсветку и стрелки.
5. Экспорт `.ikguide.json` или QR → цеховое приложение.
6. Рабочий проходит шаги, подтверждает спорные размеры (если инженер ещё не сделал этого), закрывает чек-лист.
7. Результат (кто, когда, какие подтверждения) — в журнал этапа 2+.

## 4. Этап 2 — Python OpenCV / OCR сервис

### Стек
- **FastAPI + Pydantic v2** — HTTP-сервис, JSON-схемы повторяют `IkGuideDocument` (генерируются из Zod-описания
  вручную или через `json-schema`).
- **OpenCV**: deskew, перспективная коррекция листа, бинаризация Сауволы, удаление рамки и штампа, детекция
  линий (Hough) для разделения видов.
- **OCR**: PaddleOCR (rus) как основной, Tesseract 5 (`rus+eng`, `--psm 6`) как fallback; обязательный словарь
  замен `O→0`, `З→3`, `Ч→4`, `х→×`, `Ø`-варианты.
- **Символьный слой**: классификатор знаков шероховатости (`√`), сварных швов, баз, позиций.
- **Постобработка**: регулярные выражения и таблицы **из `@ikguide/gost-translator`**, перенесённые в Python
  (единый источник значений — JSON-экспорт таблиц, чтобы числа не разъезжались).

### Контракт API
```
POST /v1/recognize            multipart: file, sheetFormat?, scale?
→ 200 {
    "schemaVersion": "1.0",
    "page": { "width": 2480, "height": 3508, "dpi": 300 },
    "annotations": [
      { "id": "ocr-1", "raw": "Ø20 H7", "kind": "fit",
        "xPercent": 56.0, "yPercent": 48.1,
        "confidence": 0.87, "source": "ocr:line-42",
        "bbox": [1210, 880, 210, 64] }
    ],
    "detectedViewId": "bracket-sheet",
    "warnings": ["Штамп не распознан — шифр введите вручную"]
  }
```
Правила:
- сервис **не** придумывает шаги и анти-ошибки — только обозначения и их координаты;
- `confidence` считается как минимум из уверенности OCR-движка, проверки формата парсером и близости к
  табличному значению; значения ниже 0.95 не «округляются вверх»;
- всё, что не прошло `translateEngineeringNotation` в Python-порте, помечается `kind: "unknown"` и не попадает
  в инструкцию автоматически.

### Интеграция с фронтендом
- В dev: `server.proxy` Vite (`/api/ocr` → `http://localhost:8000`).
- В production: сервис как sidecar Tauri (этап 4) и как отдельный контейнер для облачной версии.
- Загрузка изображения уже реализована в UI; на этапе 2 к ней добавляется вызов `/v1/recognize` и заполнение
  `xrayAnnotations`.

### Тесты этапа 2
- Golden-set из 50+ реальных чертежей (разные сканеры, штампы, масштабы).
- Метрики: recall по обозначениям, точность значений в мкм, доля ложных «уверенных» ответов (**должна быть 0** —
  иначе анти-галлюцинация не работает).

## 5. Этап 3 — 3D `.STEP` конвейер

- **Вход:** `.step/.stp` или `.iges`.
- **Сервис:** Python + `OCP`/`pythonocc-core` (OpenCascade):
  - разбор дерева сборки, габариты, массы;
  - упрощение (defeaturing) для рендера;
  - экспорт **glTF/GLB** + `scene.json` с id узлов, позициями и матрицами.
- **Фронтенд:** `three.js` + свой слой подсветки, аналогичный 2D: `shapeId` → материал трёх цветов.
- **Расширение схемы:**
  ```jsonc
  "illustration": {
    "kind": "3d",
    "sceneId": "rd12-assembly",
    "camera": { "position": [0.4, 0.3, 0.8], "target": [0, 0, 0] },
    "highlight": [{ "shapeId": "node-14", "label": "Крышка", "tone": "accent" }],
    "explode": 0.35
  }
  ```
  Поле `kind` вводится как дискриминированное объединение `vector | image | 3d`; старые документы продолжают
  открываться без миграции (по умолчанию `vector`).
- **Автошаги:** последовательность сборки из дерева сопряжений (fit → mate) с ручной правкой инженером.

## 6. Этап 4 — упаковка `.exe` и `.apk`

### Windows `.exe` — Tauri 2
- Rust-оболочка, `frontendDist` = `apps/studio-web/dist`.
- Плагины: `dialog` (открыть/сохранить `.ikguide.json`), `fs`, `printer` (печать A4 без браузера), `updater`,
  `single-instance`.
- Sidecar: локальный OCR/STEP-сервис (PyInstaller) — офлайн-цеха без интернета.
- Подпись кода (EV-сертификат) и MSI/NSIS-инсталлятор; автообновление через собственный канал.

### Android `.apk` — Capacitor 6
- `npx cap add android`, `webDir: dist`.
- Плагины: `camera` (съёмка чертежа), `filesystem` (офлайн-кэш документов), `barcode-scanner` (цеховой QR),
  `text-to-speech` (нативный TTS вместо Web Speech API, если WebView без русского голоса).
- Офлайн-first: `.ikguide.json` хранится в IndexedDB/SQLite, синхронизация — этап 5.
- Сборка: Gradle + подпись keystore в CI (Linux-раннер с Android SDK), артефакт `app-release.apk`.

### Общие требования к оболочкам
- Никаких абсолютных URL: `base: './'` и относительные `fetch`.
- Размер бандла: текущий `~375 kB` JS (gzip `~118 kB`) — бюджет до 600 kB до подключения three.js.
- Проверка печати: в Tauri — нативный драйвер, в Android — «Печать в PDF» через системный диалог.

## 7. Качество и CI

| Гейт | Команда | Текущий результат |
| --- | --- | --- |
| Unit-тесты | `npm test` | 99 тестов, 9 файлов, зелёные |
| Типы | `npm run typecheck` | 0 ошибок, strict |
| Сборка | `npm run build` | пакеты `tsc` + Vite OK |

Правила:
- новые таблицы ГОСТ — только вместе с тестами на граничные значения (номинал 3, 30, 500 мм; шаг; класс);
- изменение схемы — только с миграцией и тестом обратной совместимости;
- запрещены «магические» числа в UI: значения берутся из ядра;
- smoke-тест (`App.smoke.test.tsx`) прогоняет реальные клики: главная → проверка → шаги → рентген → инженер →
  чек-лист → финиш.

## 8. Риски и как мы их снимаем

| Риск | Влияние | Мера |
| --- | --- | --- |
| OCR «уверенно» врёт | Брак детали | Порог 0.95 в схеме, блокировка чек-листа, ручное подтверждение, `source`/`bbox` для аудита |
| Разъезд таблиц между TS и Python | Разные миллиметры в разных местах | Один JSON-экспорт таблиц, тесты-снапшоты в обоих репозиториях |
| Тяжёлый 3D ломает `.apk` | Отказ цеха | glTF с LOD, ленивая загрузка сцены, 2D-схемы остаются основным режимом |
| Тёмная тема и печать | Нечитаемые инструкции | `@media print` фиксирует светлые цвета и A4; арт всегда на белой «бумаге» |
| Потеря документа | Проcтой | Экспорт `.ikguide.json`, QR с контрольной суммой, localStorage как черновик |
