# IkGuide — «Чертёж → инструкция IKEA»

Коммерческая платформа, которая превращает чертёж по ГОСТ/ЕСКД в пошаговую инструкцию, понятную рабочему
без инженерного образования. Один и тот же React-UI используется и в цеховом Android-приложении (`.apk`),
и в десктопном редакторе инженера (`.exe`).

**Этапы 1–3 (этот репозиторий):** фундамент (схема документа, детерминированное ГОСТ-ядро без LLM,
интерфейс «Apple Freeform + IKEA 2.0» в двух режимах), **автоматическое распознавание чертежей**
(Python-сервис на OpenCV/PyMuPDF/RapidOCR, «умная камера», чтение любой области листа) и
**3D-конвейер**: `.step/.stl/.obj/.glb` → детали → порядок сборки → IKEA-схемы и живая 3D-модель.
Нативные сборки `.exe`/`.apk` сознательно не выполняются в Linux-контейнере — см. «[ARCHITECTURE.md](./ARCHITECTURE.md)».

## Что уже работает

### Режим «Рабочий» (прототип `.apk`)
Внутри рамки смартфона — шесть полноценных экранов:

| Экран | Что делает |
| --- | --- |
| **Главная** | Карточки инструкций, быстрые действия, нижняя капсула «Сфоткать / Загрузить / QR» |
| **Быстрая проверка** | Anti-hallucination: всё, что распознано с уверенностью `< 0.95`, подсвечено жёлтым и требует одного касания |
| **Перед началом работы** | Заготовка, материал, комплектация, инструмент с иконками, предупреждение о точных размерах. Для 3D-сборок — полная спецификация деталей: наименование, габарит, номер шага, количество |
| **Шаги** | Векторная схема в трёх цветах, текст от 15,5 px, контрольные размеры, красная «Анти-ошибка», озвучка `ru-RU`, крупные кнопки, свайпы и стрелки клавиатуры. Для 3D-сборок — переключатель **«Схема IKEA» / «3D-модель»** прямо над сценой |
| **Рентген чертежа** | Схематический лист с точками-пинами: тап по `Ø20 H7`, `4 отв. М8-7H глуб. 20`, `Ra 1.6`, `Т1-К5` — мгновенный перевод из ГОСТ-ядра, подтверждение спорного значения, «⌖ Выделить область» поверх листа и ручная проверка любого шифра с добавлением в черновик |
| **Чек-лист** | Финальный контроль с прогрессом и блокировкой сдачи, пока не подтверждены размеры |

### Режим «Инженер» (прототип `.exe`, Freeform-холст)
- Бесконечный холст с точечной сеткой: панорама мышью, зум `Ctrl + колесо`, перетаскивание карточек.
- Редактирование в два клика: заголовок и текст шага правятся прямо в карточке.
- Добавление / удаление / правка красной пометки «Анти-ошибка», перестановка шагов местами.
- Экспорт и импорт `.ikguide.json` с полной валидацией Zod-схемой.
- Настоящий QR-код (`qrcode`) с deep-link `ikguide://guide/<id>` и контрольной суммой документа.
- Печать / «Сохранить в PDF»: чистые листы A4 под ГОСТ/IKEA (`@media print`) — обложка, BOM, инструмент, шаг на страницу, чек-лист с подписями.
- Кнопка «Глазами рабочего» мгновенно переключает на цеховой интерфейс.
- Карточка **«3D-сборка»**: загрузка `.glb/.gltf/.stl/.obj/.step`, **«Обновить 3D-модель»**
  (пересборка инструкции по новой ревизии модели с сохранением ручных правок), **«Снять IKEA-ракурс»**
  (пересчёт SVG под выбранные азимут/наклон), экспорт шага в `.svg`.
- Перегруппировка деталей на 3D-шагах: **«Влить в предыдущий»** (четыре шайбы + четыре болта → один шаг)
  и **«Отделить деталь»**. Шаги перенумеровываются, `activePartIds`/`installedPartIds` пересчитываются,
  схемы перерисовываются офлайн.

### Сканирование: чертёж → черновик инструкции (этап 2)
- Капсула **«📷 Чертёж → инструкция»** на верхней панели открывает диалог сканирования.
- **Умная камера**: задняя камера телефона, подсказки «больше света / поднимите телефон / резче» по
  реальным метрикам (яркость и дисперсия лапласиана), съёмка в JPEG; или загрузка PDF/PNG/JPEG — до 6 листов.
- Сервис `services/vision-api` находит лист, выправляет перспективу, снимает тени, читает **штамп**
  (название, шифр, материал, масштаб) и обозначения с координатами. Векторный PDF читается из
  символьного слоя — точно; фото — через RapidOCR.
- Диалог показывает стадии распознавания и результат: листов, распознано, на проверку, инструментов,
  контрольных точек. Всё с уверенностью `< 0.95` остаётся неподтверждённым.
- **«Рентген»**: тап по пину — перевод по ГОСТ; **«⌖ Выделить область»** — обвести пропущенный размер
  пальцем и перечитать только эту область; **ручной шифр** (`Ø32 H7/k6`, `М10×1,25`, `Ra 0.8`…)
  добавляется в черновик инструкции как подтверждённое человеком обозначение.
- Черновик собирается детерминированно (`@ikguide/builder`): инструмент под каждое обозначение,
  пять стадий обработки, контрольные точки, предупреждения о том, что не прочитано.
- **Сервис офлайн — не ошибка**: демо-проекты и уже открытые инструкции работают как обычно,
  диалог объясняет `npm run dev:vision` и предлагает ручной путь.

### 3D-конвейер: `.STEP` → IKEA-схема → 3D-модель (этап 3)
- **Сервис** `services/cad-api` (FastAPI, порт 8001, рядом с `vision-api`): читает `.step/.stp/.stl/.obj/.glb/.gltf`,
  нормализует единицы и масштаб, режет сборку на детали с стабильными `node.name`, считает габариты, объёмы
  и центры масс, упаковывает всё в один оптимизированный `.glb`.
- **Порядок сборки** вычисляется «обратной разборкой»: граф касаний по AABB, снятие деталей снаружи внутрь,
  затем инверсия. Одинаковый крепёж одного узла склеивается в один шаг: «Закрути 4 болта М6×20 крест-накрест».
  Роли `base / part / fastener` определяются по названию (`болт`, `винт`, `шайба`, `ГОСТ`, `DIN`, `М6`…)
  и по объёму.
- **IKEA-схемы** — только векторный SVG, ровно три смысловых цвета: установленное `#FFFFFF`/`#F2F4F7`
  с контуром `#1D1D1F`, активная деталь `#E8F2FF` с контуром `#007AFF`, критическая ориентация — `#FF3B30`.
  Активная деталь сдвинута по своему вектору сборки, ось показана пунктиром и жирной синей стрелкой.
- **Живая 3D-модель** (`three.js`, отдельный чанк): белый матовый пластик с тёмным контуром для
  установленного, синяя подсветка активной детали, «влёт» по оси сборки, слайдер «Разнести / Собрать»,
  кнопка «Повторить анимацию установки», призрачные контуры будущих деталей, орбита и зум мышью и пальцем.
- **Одно обновление = новая инструкция**: `mergeCadUpdate` сопоставляет детали по `nodeName` и обновляет
  шаги, сохраняя изменённые тексты, «Анти-ошибки», ракурсы и чек-лист. Инженер видит тост
  «Модель обновлена: +1 деталь, ручные пометки сохранены», ревизия документа растёт `A → B`.
- **Офлайн — норма**: третий демо-проект «Узел привода УП-08» (12 деталей, 6 шагов, процедурный `.glb`
  внутри бандла) работает без сети и без сервиса; `.glb/.gltf`, загруженный в браузере, разбирается
  локально (`cadOffline.ts`), `.step` честно просит `npm run dev:cad`.

### Цех без сети: `.exe`, `.apk`, QR и офлайн-библиотека (этап 4)
- **Один бандл — три оболочки**: браузер (dev/preview), Windows `.exe` (Tauri 2) и Android `.apk`
  (Capacitor 6). `runtimeConfig.ts` сам понимает, где он запущен: в браузере запросы остаются
  относительными (`Vite`-прокси), в нативной оболочке к ним подставляется адрес цехового сервера.
  Стартовый режим тоже разный: планшет открывается как «Рабочий», `.exe` — как «Инженер».
- **«Настройки и подключение»** (шестерёнка в верхней капсуле): два адреса сервисов, подсказка
  локального IP одной кнопкой, «Проверить связь» — реальные запросы к `/health` и `/v1/cad/health`
  с версией OpenCV, движком OCR и доступностью STEP, и переключатель **«Строгий режим цеха»**,
  который убирает редактор инженера с планшета.
- **QR-мост**: инструкция сжимается (`fflate` + base64url) и целиком уезжает в ссылку
  `<адрес>/?g=<payload>` — телефону не нужны ни сеть, ни приложение. Код вмещает ~2.5 КБ, поэтому
  тяжёлые части отбрасываются **в объявленном порядке** и с честным предупреждением: сначала `.glb`
  («В QR упакованы все шаги, инструмент, ГОСТ-переводы и SVG-схемы; для полного 3D-файла передайте
  пакет `.ikguide.json` по сети»), затем `assembly3d`, затем SVG-схемы, затем переводы обозначений.
  Если не влезает даже самое компактное представление — диалог прямо говорит «не помещается» и
  предлагает вторую вкладку.
- **Вторая вкладка «QR по цеховой ссылке»**: короткая ссылка на инструкцию на цеховом сервере —
  работает на `.apk` и на iPhone, нужен только Wi-Fi цеха.
- **Сканер QR-кода**: живой поток камеры с рамкой прицела (`jsqr`, всё локально), кнопка «Выбрать
  фото QR-кода из галереи» и поле для ссылки/кода вручную. Распознанная инструкция проверяется
  схемой, сохраняется офлайн и сразу открывается на «Перед началом работы». Ссылка `?g=…` или
  `?guide=…` в адресной строке открывает инструкцию при старте приложения.
- **Офлайн-библиотека** (`IndexedDB`, с откатом на `localStorage` и память): всё созданное,
  импортированное и отсканированное остаётся на устройстве. На главном экране рабочего — блок
  «Доступно офлайн» с пином и удалением, у инженера — панель «На устройстве».
- **Пакет и автономный HTML**: «Скачать автономный офлайн-пакет (`.ikguide.json`)» и «Экспорт
  автономного HTML-файла» — один самодостаточный `.html` без скриптов и сети, со встроенными SVG,
  инструментом и чек-листом. В `.exe` те же кнопки открывают нативный диалог сохранения.
- **Сборка `.exe`/`.apk` — в GitHub Actions** (`.github/workflows/release-builds.yml`): Windows-раннер
  собирает `.exe` через Tauri, Linux-раннер — `.apk` через Capacitor + Gradle. Готовые файлы лежат в
  Artifacts каждого запуска и прикрепляются к Release по тегу `v1.0.0`.

### Мгновенный цеховой QR-мост (этап 5)
- **Инструкция публикуется на ноутбуке цеха и получает короткий код** (например `pgcvbpv3`).
  `POST /v1/guides` принимает полный `.ikguide.json` **вместе с 3D-моделью** (до 64 МБ), кладёт его рядом
  с сервисом (`services/vision-api/data/guides`, каталог переопределяется `IKGUIDE_GUIDES_DIR`) и
  возвращает код из 8 символов без похожих знаков (`0/o/1/l` исключены — код диктуют голосом и печатают
  руками; регистр в ссылке не важен).
- **Повторная публикация ничего не дублирует**: документ опознаётся по SHA-256, ответ приходит с тем же
  кодом и `deduplicated: true`. На диске живут 200 последних публикаций, самые старые вытесняются
  (порядок — по монотонному номеру, а не по точности `mtime` файловой системы).
- **QR помещается всегда, потому что в нём не инструкция, а адрес**: `http://192.168.1.50:8000/?guideId=pgcvbpv3&api=http://192.168.1.50:8000`
  — 70 байт вместо 4–5 КБ. Телефон открывает приложение, скачивает инструкцию **целиком** (3D-узел,
  SVG-схемы, ГОСТ-переводы), сохраняет её офлайн и запоминает адрес сервера из `api`, чтобы следующее
  открытие работало без ссылки.
- **Цеховой сервер сам знает свой LAN-адрес**: `GET /v1/network-info` отдаёт адрес исходящего интерфейса,
  имя хоста, порт и готовую подсказку `suggestedApiBase`. `169.254.x.x` честно помечается `link-local`
  и не выдаётся за цеховую сеть, а `absoluteUrl` публикации не отдаёт телефону `127.0.0.1`.
- **Студия отдаётся тем же сервером**: собранный `apps/studio-web/dist` монтируется на `/` и `/studio`
  (`IKGUIDE_STUDIO_DIST` переопределяет путь), поэтому ссылка из QR открывается на телефоне без
  dev-сервера и без интернета. Если бандл не собран, `/` отвечает JSON — API от этого не ломается.
- **Сбой сервера не останавливает смену**: скачанная копия помнит свой короткий код (`publishedCode` в
  офлайн-библиотеке), поэтому та же ссылка открывает инструкцию и без сети. В диалоге QR рядом с
  публикацией остаются автономный QR, пакет `.ikguide.json` и HTML-файл — отказ сервера объясняется
  по-русски, без «код 500».

### Ядро ГОСТ/ЕСКД — 100 % детерминированное, без LLM
`packages/gost-translator` — таблицы и парсеры, один и тот же ввод всегда даёт один и тот же вывод:

| Семейство | Покрытие |
| --- | --- |
| **Метрическая резьба** (ГОСТ 24705, ГОСТ 19257-73, ГОСТ 11284-75) | `М8`, `М8-7H`, `М10×1,25`, `4 отв. М6-7H глуб. 15`, `М12-6g`: шаг, сверло под резьбу (М8 → Ø6,8), проходное отверстие, размер ключа, глубина, инструмент |
| **Допуски и посадки** (ГОСТ 25346 / ISO 286, 1–500 мм) | `Ø20 H7`, `Ø32 H7/k6`, `50 h6`, `Ø16 JS7`, `12 H11`, `Ø25 f7`, `Ø40 g6`, `Ø20 d9`: отклонения в мкм, годный размер, тип посадки, совет «сверло или развёртка + калибр» |
| **Шероховатость** (ГОСТ 2789-73) | `Ra 0.8`, `Ra 1.6`, `Ra 3.2`, `Ra 6.3`, `Rz 20`, `Rz 40` → класс, группа обработки, способ получения, тактильное описание |
| **Сварные швы** (ГОСТ 5264-80, ГОСТ 2.312-72) | `С2`, `У4`, `Т1`, `Н1`, катет `К4/К6`, прерывистый `50/100`, замкнутый контур, зачистка заподлицо: инструкция сварщику с током и электродом |
| **Фаски, радиусы, группы отверстий, размеры** | `2×45°`, `1,5×45°`, `C3`, `R3`, `4 отв. Ø6,5`, `120±0,5`, `20 +0,1/-0,05` |

Каждый ответ содержит: точные миллиметры и микрометры, понятное объяснение, практический совет рабочему,
список инструмента и предупреждения о нестандартных или неподдерживаемых обозначениях.

        └── src/art/              # векторные схемы шагов и листы чертежей (3 цвета)
        └── src/components/worker # 6 экранов цеха (включая ROI на «Рентгене»)

### Демо-проекты (встроены, без пустых экранов)

## Быстрый старт

Требования: **Node.js ≥ 20.11**, npm ≥ 10, **Python ≥ 3.10** (только для распознавания чертежей).

```bash
npm install            # установка зависимостей всех workspaces
npm run dev            # http://localhost:5173 — студия в режиме рабочего
npm run dev:vision     # в отдельном терминале: сервис распознавания на 127.0.0.1:8000
npm run dev:cad        # в третьем терминале: сервис 3D-моделей на 127.0.0.1:8001
npm run dev:all        # либо всё сразу (vision + cad + студия)
```

`npm run dev:vision` сам создаёт `services/vision-api/.venv`, ставит зависимости (OpenCV, PyMuPDF,
FastAPI) и поднимает uvicorn с автоперезагрузкой. OCR ставится отдельно (`requirements-ocr.txt`);
без него сервис работает с векторными PDF и честно сообщает `ocr: "none"`.
`npm run dev:cad` создаёт `services/cad-api/.venv` и ставит `trimesh`, `numpy`, `scipy` и `cascadio`
(тесселяция STEP). Без `cascadio` сервис поднимается в режиме «только меши» и честно отвечает
`stepEnabled: false` с подсказкой; `.stl/.obj/.glb/.gltf` продолжают работать.

Адреса сервисов меняются переменными `VITE_VISION_API_URL` и `VITE_CAD_API_URL` — Vite проксирует
`/v1/cad` в CAD-сервис, остальной `/v1` и `/health` в сервис распознавания, поэтому браузер всегда
ходит по относительным путям и работает в песочнице предпросмотра и внутри упакованных оболочек.

Проверки качества (те же команды, что в CI):

```bash
npm test            # Vitest: 267 тестов, 25 файлов
npm run test:vision # pytest: 129 тестов сервиса распознавания
npm run test:cad    # pytest: 44 теста сервиса 3D-моделей
npm run typecheck   # tsc --noEmit, 0 ошибок
npm run build       # packages tsc + Vite production build
npm run check:native # 127 проверок Tauri/Capacitor/workflow/иконок (то, что собирается только в CI)
```

## Как скачать готовые `.exe` и `.apk` через GitHub Actions

Собирать нативное приложение локально не нужно: оба установщика собираются на чужих раннерах
(Windows — Tauri, Linux — Gradle), а в репозитории лежат только исходники, конфиги и иконки.

### Вариант 1 — запустить сборку вручную (без тега)

1. Откройте вкладку **Actions** репозитория.
2. Слева выберите **Release builds**.
3. Кнопка **Run workflow** → ветка (обычно `main`) → **Run workflow**.
4. Дождитесь зелёной галочки (первый запуск ~10–15 минут: Rust-кэш и Gradle пустые).
5. Внизу страницы запуска, в блоке **Artifacts**, скачайте:
   - **`ikguide-studio-windows`** → `ikguide-studio-windows.exe` (portable) и `ikguide-studio-setup.exe` (NSIS);
   - **`ikguide-worker-android`** → `ikguide-worker-android.apk` (debug, ставится на планшет);
   - **`ikguide-workshop-backend`** → архив с Python-сервисами и скриптом запуска для цехового ПК.

### Вариант 2 — выпустить версию тегом (Release с файлами)

```bash
git tag v1.0.0
git push origin v1.0.0
```

Тег `v*` запускает тот же workflow и дополнительно прикрепляет `.exe`, `.apk` и архив бэкенда к
**GitHub Release** — рабочим можно отдавать прямые ссылки на скачивание.

### Установка на планшет (Android)

1. Скачайте `ikguide-worker-android.apk` на планшет (или передайте файлом).
2. Разрешите установку из этого источника, если Android спросит.
3. Откройте приложение → шестерёнка → «Настройки и подключение» → впишите адрес цехового ноутбука
   (например `http://192.168.1.50:8000` и `http://192.168.1.50:8001`) → «Проверить связь».
4. Для планшета, который не должен показывать редактор инженера, включите **«Строгий режим цеха»**.

Debug-APK подписан отладочным ключом и обновляется только переустановкой. Для боевой подписи
добавьте секреты `IKGUIDE_KEYSTORE_BASE64`, `IKGUIDE_KEYSTORE_PASSWORD`, `IKGUIDE_KEY_ALIAS`,
`IKGUIDE_KEY_PASSWORD` — workflow соберёт `ikguide-worker-android-release.apk` (шаг помечен
`continue-on-error`, поэтому без секретов сборка не падает).

### Установка на Windows (`.exe`)

- `ikguide-studio-setup.exe` — установщик NSIS (для текущего пользователя, без прав администратора);
- `ikguide-studio-windows.exe` — переносимый файл: положите на флешку, запустите, ничего не ставится.

SmartScreen покажет предупреждение о неизвестном издателе: подпись EV-сертификатом — отдельная задача,
кода она не касается.

## Цеховой сервер на Windows (локальная сеть без интернета)

Оба Python-сервиса работают на обычном ноутбуке цеха; планшет ходит к ним по Wi-Fi, ничего наружу
не уходит.

```bat
:: один раз: Python 3.11 с python.org, галочка «Add python.exe to PATH»
scripts\start-workshop-servers.bat install
:: каждый рабочий день:
scripts\start-workshop-servers.bat
```

Скрипт печатает адреса (`http://192.168.1.50:8000/health` и `http://192.168.1.50:8001/v1/cad/health`)
и открывает `/health` в браузере. Это же окно показывает, какие адреса вписать на планшете.

Тот же сервер раздаёт студию и опубликованные инструкции (этап 5):

| Адрес | Что это |
| --- | --- |
| `http://<LAN-IP>:8000/` | студия из `apps/studio-web/dist` (после `npm run build`) — по этой ссылке открывается QR цеха |
| `http://<LAN-IP>:8000/?guideId=<код>&api=http://<LAN-IP>:8000` | конкретная опубликованная инструкция |
| `GET /v1/guides`, `GET /v1/guides/<код>` | список публикаций и сам документ |
| `POST /v1/guides` | публикация из диалога QR (до 64 МБ, 200 последних инструкций) |
| `GET /v1/network-info` | как сервер видит себя в цеховой сети |

Инструкции лежат в `services/vision-api/data/guides` (в git не попадают); каталог меняется переменной
`IKGUIDE_GUIDES_DIR`, адрес в подсказке — `IKGUIDE_LAN_IP`, если у ноутбука несколько сетевых карт.
Останавливаются сервисы закрытием окон; ярлык на скрипт можно положить на рабочий стол.
Тот же архив и скрипт лежат в Artifacts (`ikguide-workshop-backend`).

Для Linux/macOS то же самое: `bash scripts/start-workshop-servers.sh install` и затем
`npm run workshop:servers`.

## Формат `.ikguide.json`

Единый документ, которым обмениваются редактор и цеховое приложение (схема `schemaVersion: "1.0"`):

```jsonc
{
  "schemaVersion": "1.0",
  "id": "guide-ks04-bracket",
  "metadata": { "title": "…", "drawingCode": "КС-04.100.000 СБ", "material": "…", "blankDimensions": "…", "difficulty": "medium", "author": "…", "createdAt": "2026-11-12T08:30:00.000Z", "revision": "B" },
  "drawing": { "viewId": "bracket-sheet", "sheetFormat": "A3", "scale": "1:1" },
  "bom": [{ "id": "bom-bolt", "name": "Болт", "size": "М8 × 30", "quantity": 4, "kind": "fastener", "icon": "bolt", "standard": "ГОСТ 7798-70" }],
  "tools": [{ "id": "tool-drill", "name": "Сверло", "size": "Ø6,8 мм", "category": "drill", "purpose": "…", "forSteps": [2] }],
  "steps": [{
    "id": "step-1", "number": 1, "title": "…", "workerText": "…", "estimatedMinutes": 8,
    "illustration": { "illustrationId": "bracket-layout", "highlight": [{ "shapeId": "plate", "label": "Заготовка", "tone": "accent" }], "arrows": [] },
    "antiError": { "text": "Не размечайте от двух кромок…", "severity": "warning" },
    "criticalChecks": [{ "id": "check-blank", "label": "Габарит", "nominal": "120 × 80 × 12", "acceptance": "±1,0 мм", "instrument": "Штангенциркуль" }],
    "drawingRefs": ["ann-dim-18"]
  }],
  "xrayAnnotations": [{
    "id": "ann-dim-18", "raw": "18", "kind": "dimension",
    "xPercent": 42, "yPercent": 27, "confidence": 0.62,
    "confirmedByHuman": false, "ambiguousOptions": ["12 мм", "18 мм"]
  }],
  "qcChecklist": [{ "id": "qc-fit", "text": "Ø20 H7 в допуске…", "required": true, "reference": "Ø20 H7" }],

  // Необязательный блок 3D-сборки (обратная совместимость: старые документы его просто не имеют)
  "assembly3d": {
    "glbDataUrl": "data:model/gltf-binary;base64,…",
    "sourceFormat": "step",
    "units": "mm",
    "sizeMm": { "x": 120, "y": 80, "z": 67 },
    "massKg": 2.18,
    "revision": "A",
    "parts": [{
      "id": "part-1", "nodeName": "korpus", "displayName": "Корпус", "role": "base",
      "stepNumber": 1, "explosionVector": [0, -1, 0], "bboxMm": { "x": 120, "y": 40, "z": 80 }
    }]
  }
}
```

Шаг 3D-документа дополнительно несёт `activePartIds`, `installedPartIds`, `cameraView {azimuth, elevation}` и
`svgDiagram` — готовую IKEA-схему. Схема проверяет, что активная деталь не бывает одновременно установленной,
что `stepNumber` не выходит за число шагов и что `svgDiagram` начинается с `<svg`.

Схема проверяет не только типы, но и смысл: уникальность шагов и аннотаций, последовательность номеров,
существование `drawingRefs`, диапазон `confidence`, минимум два варианта в `ambiguousOptions`.
Ошибки возвращаются читаемыми русскими сообщениями.

### Anti-hallucination
Порог `CONFIDENCE_THRESHOLD = 0.95` живёт в ядре схемы. Всё, что ниже, блокирует сдачу детали, пока человек
не подтвердит значение (одно касание или выбор из `ambiguousOptions`). Подтверждённое значение сохраняется в
`resolvedValue` и дальше используется вместо догадки OCR.

## Ограничения (честно)

- Распознавание работает **только при запущенном сервисе** (`npm run dev:vision`). Без него студия живёт
  в ручном режиме: лист как подложка, шифры вводятся вручную — и это явно объясняется в диалоге.
- Фото-OCR латинизирует кириллицу: цифры, `Ø`, `Ra`, резьбы и посадки читаются, а имя детали надёжнее
  брать из штампа векторного PDF. Тесты фото-листов поэтому проверяют геометрию и цифровые токены.
- Пока не подключён `rapidocr-onnxruntime`, сервис отвечает `ocr: "none"` и обрабатывает только
  PDF/сканы с текстовым слоем. Системного Tesseract в контейнере нет.
- Автоопределение габарита заготовки по видам — эвристика: если не нашлось, в инструкции будет
  `Габарит заготовки уточнить у инженера` и предупреждение (лучше честно, чем выдумать размер).
- **Опубликованная инструкция живёт на ноутбуке цеха**: первый показ требует Wi-Fi, дальше работает
  сохранённая копия. Отдельного «облака» нет осознанно — наружу из цеха ничего не уходит.
- **Хранилище публикаций ограничено** 200 инструкциями и 64 МБ на документ; вытесняются самые старые.
  Для больших сборок остаются `.ikguide.json` по сети и автономный HTML.
- **`.exe` и `.apk` не собираются в песочнице разработки**: в ней нет `rustc`, `cargo`, JDK, Gradle и
  Android SDK. Поэтому конфиги Tauri/Capacitor, Rust-исходники, полный Gradle-проект, иконки и CI
  проверяются статически (`npm run check:native` — 127 проверок), а Rust компилируется в CI
  (`cargo check` в джобе `rust-tauri-check`), настоящие бинарники собирает GitHub Actions. Ни `cargo check`, ни `gradlew assembleDebug` здесь не запускались — это указано
  честно, а не замаскировано зелёным статусом.
- **В QR помещается ~2.5 КБ**: шестишаговая инструкция с проверками сжимается до 4–5 КБ, поэтому
  большие инструкции физически не влезают в один код. Диалог QR в этом случае честно пишет
  «не помещается» и предлагает цеховую ссылку, пакет `.ikguide.json` или автономный HTML.
- **Cleartext-HTTP в Android** разрешён осознанно (цеховой сервер без сертификата): ограничить его
  диапазонами `192.168.*.*` через `network_security_config.xml` нельзя — это список доменов, а не
  подсеть; компенсация — приложение цеха, а не браузер, и явные записи для `localhost`/`10.0.2.2`.
- **Подпись release-APK** требует ваших секретов в GitHub: без них собирается debug-APK.
- **Камера в WebView** отдана Capacitor: Android спрашивает разрешение CAMERA сам; если политика
  планшета запрещает камеру, сканер работает через фото из галереи и ручную ссылку.
- Озвучка использует Web Speech API: голос зависит от системы. Если русского голоса нет, шаг просто не
  прочитается — покажем уведомление.
- Документы сохраняются в `localStorage` браузера; облачная синхронизация — вне этапа 1.
- `.step/.stp` разбирает **только сервис** (`cascadio`): в Linux-контейнере `cadquery-ocp` не ставится из-за
  отсутствия `libGL`, поэтому вторым движком STEP остаётся `cascadio`, а без него — режим «только меши».
- Офлайн-разбор `.glb/.gltf` в браузере (`cadOffline.ts`) — черновой: объёмы берутся по габаритам, порядок
  шагов сортируется по размеру, а не моделируется разборкой. Такой черновик помечается предупреждением.
- Офлайновый SVG-рендер (`ikeaSvg.ts`) рисует силуэты AABB: он нужен, чтобы шаг всегда печатался, но
  «настоящие» рёбра силуэта из треугольников даёт только сервис.
- STEP/IGES с точными отверстиями не просверливаются в модели: болт проходит «сквозь» плиту, если в
  исходнике нет отверстия. Секвенсор это терпит (крепёж уходит в последние шаги), но физику не выдумывает.
