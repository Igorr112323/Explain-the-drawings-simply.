# IkGuide — «Чертёж → инструкция IKEA»

Коммерческая платформа, которая превращает чертёж по ГОСТ/ЕСКД в пошаговую инструкцию, понятную рабочему
без инженерного образования. Один и тот же React-UI используется и в цеховом Android-приложении (`.apk`),
и в десктопном редакторе инженера (`.exe`).

**Этапы 1–2 (этот репозиторий):** фундамент (схема документа, детерминированное ГОСТ-ядро без LLM,
интерфейс «Apple Freeform + IKEA 2.0» в двух режимах) **и автоматическое распознавание чертежей**:
Python-сервис на OpenCV/PyMuPDF/RapidOCR, «умная камера», чтение любой области листа и сборка
черновика инструкции из ответа сервиса.
Нативные сборки `.exe`/`.apk` сознательно не выполняются в Linux-контейнере — см. «[ARCHITECTURE.md](./ARCHITECTURE.md)».

## Что уже работает

### Режим «Рабочий» (прототип `.apk`)
Внутри рамки смартфона — шесть полноценных экранов:

| Экран | Что делает |
| --- | --- |
| **Главная** | Карточки инструкций, быстрые действия, нижняя капсула «Сфоткать / Загрузить / QR» |
| **Быстрая проверка** | Anti-hallucination: всё, что распознано с уверенностью `< 0.95`, подсвечено жёлтым и требует одного касания |
| **Перед началом работы** | Заготовка, материал, комплектация, инструмент с иконками, предупреждение о точных размерах |
| **Шаги** | Векторная схема в трёх цветах, текст от 15,5 px, контрольные размеры, красная «Анти-ошибка», озвучка `ru-RU`, крупные кнопки, свайпы и стрелки клавиатуры |
| **Рентген чертежа** | Схематический лист с точками-пинами: тап по `Ø20 H7`, `4 отв. М8-7H глуб. 20`, `Ra 1.6`, `Т1-К5` — мгновенный перевод из ГОСТ-ядра, подтверждение спорного значения, «⌖ Выделить область» поверх листа и ручная проверка любого шифра с добавлением в черновик |
| **Чек-лист** | Финальный контроль с прогрессом и блокировкой сдачи, пока не подтверждены размеры |

### Режим «Инженер» (прототип `.exe`, Freeform-холст)
- Бесконечный холст с точечной сеткой: панорама мышью, зум `Ctrl + колесо`, перетаскивание карточек.
- Редактирование в два клика: заголовок и текст шага правятся прямо в карточке.
- Добавление / удаление / правка красной пометки «Анти-ошибка», перестановка шагов местами.
- Экспорт и импорт `.ikguide.json` с полной валидацией Zod-схемой.
- Настоящий QR-код (`qrcode`) с deep-link `ikguide://guide/<id>` и контрольной суммой документа.
- Печать / «Сохранить в PDF»: чистые листы A4 под ГОСТ/IKEA (`@media print`) — обложка, BOM, инструмент, шаг на страницу, чек-лист с подписями.
- Кнопка «Глазами рабочего» мгновенно переключает на цеховой интерфейс.

### Сканирование: чертёж → черновик инструкции (этап 2)
- Капсула **«📷 Чертёж → инструкция»** на верхней панели открывает диалог сканирования.
- **Умная камера**: задняя камера телефона, подсказки «больше света / поднимите телефон / резче» по
  реальным метрикам (яркость и дисперсия лапласиана), съёмка в JPEG; или загрузка PDF/PNG/JPEG — до 6 листов.
- Сервис `services/vision-api` находит лист, выправляет перспективу, снимает тени, читает **штамп**
  (название, шифр, материал, масштаб) и обозначения с координатами. Векторный PDF читается из
  символьного слоя — точно; фото — через RapidOCR.
- Диалог показывает стадии распознавания и результат: листов, распознано, на проверку, инструментов,
  контрольных точек. Всё с уверенностью `< 0.95` остаётся неподтверждённым.
- **«Рентген»**: тап по пину — перевод по ГОСТ; **«⌖ Выделить область»** — обвести пропущенный размер
  пальцем и перечитать только эту область; **ручной шифр** (`Ø32 H7/k6`, `М10×1,25`, `Ra 0.8`…)
  добавляется в черновик инструкции как подтверждённое человеком обозначение.
- Черновик собирается детерминированно (`@ikguide/builder`): инструмент под каждое обозначение,
  пять стадий обработки, контрольные точки, предупреждения о том, что не прочитано.
- **Сервис офлайн — не ошибка**: демо-проекты и уже открытые инструкции работают как обычно,
  диалог объясняет `npm run dev:vision` и предлагает ручной путь.

### Ядро ГОСТ/ЕСКД — 100 % детерминированное, без LLM
`packages/gost-translator` — таблицы и парсеры, один и тот же ввод всегда даёт один и тот же вывод:

| Семейство | Покрытие |
| --- | --- |
| **Метрическая резьба** (ГОСТ 24705, ГОСТ 19257-73, ГОСТ 11284-75) | `М8`, `М8-7H`, `М10×1,25`, `4 отв. М6-7H глуб. 15`, `М12-6g`: шаг, сверло под резьбу (М8 → Ø6,8), проходное отверстие, размер ключа, глубина, инструмент |
| **Допуски и посадки** (ГОСТ 25346 / ISO 286, 1–500 мм) | `Ø20 H7`, `Ø32 H7/k6`, `50 h6`, `Ø16 JS7`, `12 H11`, `Ø25 f7`, `Ø40 g6`, `Ø20 d9`: отклонения в мкм, годный размер, тип посадки, совет «сверло или развёртка + калибр» |
| **Шероховатость** (ГОСТ 2789-73) | `Ra 0.8`, `Ra 1.6`, `Ra 3.2`, `Ra 6.3`, `Rz 20`, `Rz 40` → класс, группа обработки, способ получения, тактильное описание |
| **Сварные швы** (ГОСТ 5264-80, ГОСТ 2.312-72) | `С2`, `У4`, `Т1`, `Н1`, катет `К4/К6`, прерывистый `50/100`, замкнутый контур, зачистка заподлицо: инструкция сварщику с током и электродом |
| **Фаски, радиусы, группы отверстий, размеры** | `2×45°`, `1,5×45°`, `C3`, `R3`, `4 отв. Ø6,5`, `120±0,5`, `20 +0,1/-0,05` |

Каждый ответ содержит: точные миллиметры и микрометры, понятное объяснение, практический совет рабочему,
список инструмента и предупреждения о нестандартных или неподдерживаемых обозначениях.

## Быстрый старт

Требования: **Node.js ≥ 20.11**, npm ≥ 10, **Python ≥ 3.10** (только для распознавания чертежей).

```bash
npm install            # установка зависимостей всех workspaces
npm run dev            # http://localhost:5173 — студия в режиме рабочего
npm run dev:vision     # в отдельном терминале: сервис распознавания на 127.0.0.1:8000
```

`npm run dev:vision` сам создаёт `services/vision-api/.venv`, ставит зависимости (OpenCV, PyMuPDF,
FastAPI) и поднимает uvicorn с автоперезагрузкой. OCR ставится отдельно (`requirements-ocr.txt`);
без него сервис работает с векторными PDF и честно сообщает `ocr: "none"`.
Адрес сервиса меняется переменной `VITE_VISION_API_URL` — Vite проксирует `/v1` и `/health`,
поэтому браузер всегда ходит по относительным путям.

Проверки качества (те же команды, что в CI):

```bash
npm test           # Vitest: 136 тестов, 13 файлов
npm run test:vision # pytest: 98 тестов сервиса распознавания
npm run typecheck  # tsc --noEmit, 0 ошибок
npm run build      # packages tsc + Vite production build
```

Полезные скрипты:

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Vite dev-сервер студии (общий UI для `.apk` и `.exe`) |
| `npm test` / `npm run test:watch` | все unit- и smoke-тесты |
| `npm run typecheck` | строгая проверка типов всего монорепо |
| `npm run build` | сборка пакетов (`dist/`) и production-бандла студии |
| `npm run build:packages` | только пакеты ядра (schema → translator → builder) |
| `npm run dev:vision` | сервис распознавания: venv, зависимости, uvicorn `0.0.0.0:8000` |
| `npm run install:vision` | только установка Python-зависимостей |
| `npm run test:vision` | pytest сервиса распознавания (98 тестов) |

## Формат `.ikguide.json`

Единый документ, которым обмениваются редактор и цеховое приложение (схема `schemaVersion: "1.0"`):

```jsonc
{
  "schemaVersion": "1.0",
  "id": "guide-ks04-bracket",
  "metadata": { "title": "…", "drawingCode": "КС-04.100.000 СБ", "material": "…", "blankDimensions": "…", "difficulty": "medium", "author": "…", "createdAt": "2026-11-12T08:30:00.000Z", "revision": "B" },
  "drawing": { "viewId": "bracket-sheet", "sheetFormat": "A3", "scale": "1:1" },
  "bom": [{ "id": "bom-bolt", "name": "Болт", "size": "М8 × 30", "quantity": 4, "kind": "fastener", "icon": "bolt", "standard": "ГОСТ 7798-70" }],
  "tools": [{ "id": "tool-drill", "name": "Сверло", "size": "Ø6,8 мм", "category": "drill", "purpose": "…", "forSteps": [2] }],
  "steps": [{
    "id": "step-1", "number": 1, "title": "…", "workerText": "…", "estimatedMinutes": 8,
    "illustration": { "illustrationId": "bracket-layout", "highlight": [{ "shapeId": "plate", "label": "Заготовка", "tone": "accent" }], "arrows": [] },
    "antiError": { "text": "Не размечайте от двух кромок…", "severity": "warning" },
    "criticalChecks": [{ "id": "check-blank", "label": "Габарит", "nominal": "120 × 80 × 12", "acceptance": "±1,0 мм", "instrument": "Штангенциркуль" }],
    "drawingRefs": ["ann-dim-18"]
  }],
  "xrayAnnotations": [{
    "id": "ann-dim-18", "raw": "18", "kind": "dimension",
    "xPercent": 42, "yPercent": 27, "confidence": 0.62,
    "confirmedByHuman": false, "ambiguousOptions": ["12 мм", "18 мм"]
  }],
  "qcChecklist": [{ "id": "qc-fit", "text": "Ø20 H7 в допуске…", "required": true, "reference": "Ø20 H7" }]
}
```

Схема проверяет не только типы, но и смысл: уникальность шагов и аннотаций, последовательность номеров,
существование `drawingRefs`, диапазон `confidence`, минимум два варианта в `ambiguousOptions`.
Ошибки возвращаются читаемыми русскими сообщениями.

### Anti-hallucination
Порог `CONFIDENCE_THRESHOLD = 0.95` живёт в ядре схемы. Всё, что ниже, блокирует сдачу детали, пока человек
не подтвердит значение (одно касание или выбор из `ambiguousOptions`). Подтверждённое значение сохраняется в
`resolvedValue` и дальше используется вместо догадки OCR.

## Ограничения (честно)

- Распознавание работает **только при запущенном сервисе** (`npm run dev:vision`). Без него студия живёт
  в ручном режиме: лист как подложка, шифры вводятся вручную — и это явно объясняется в диалоге.
- Фото-OCR латинизирует кириллицу: цифры, `Ø`, `Ra`, резьбы и посадки читаются, а имя детали надёжнее
  брать из штампа векторного PDF. Тесты фото-листов поэтому проверяют геометрию и цифровые токены.
- Пока не подключён `rapidocr-onnxruntime`, сервис отвечает `ocr: "none"` и обрабатывает только
  PDF/сканы с текстовым слоем. Системного Tesseract в контейнере нет.
- Автоопределение габарита заготовки по видам — эвристика: если не нашлось, в инструкции будет
  `Габарит заготовки уточнить у инженера` и предупреждение (лучше честно, чем выдумать размер).
- `.exe`/`.apk` не собираются в Linux-контейнере: ядро, UI и сборка проверены через Node/Vite, упаковка — этап 4.
- Озвучка использует Web Speech API: голос зависит от системы. Если русского голоса нет, шаг просто не
  прочитается — покажем уведомление.
- Документы сохраняются в `localStorage` браузера; облачная синхронизация — вне этапа 1.
