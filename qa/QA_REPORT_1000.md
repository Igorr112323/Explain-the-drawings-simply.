## Что именно проверялось

Цепочка без единого мока:

```
файл → POST /v1/recognize (uvicorn + RapidOCR + OpenCV)
     → ikguide-builder (сборка инструкции, спецификация, виды, кропы)
     → gost-translator (обозначения ГОСТ)
     → ikguide-schema (валидация документа)
     → pdf-exporter (план + jsPDF, настоящие байты .pdf)
     → PyMuPDF (обратная проверка готового файла)
```

Мокается только браузерный canvas при нарезке кропов: в Node нет `canvas`, поэтому
`scripts/qa/build_docs.ts` повторяет ту же геометрию (`cropPercent`, `fragmentBox`) на `pngjs`.
Это отражено в P2-3 файла `qa/BUGS_FOUND.md`.

## Дополнительная итерация: полнота и переносы

Повторная сборка 1 036 инструкций на **сохранённых прежних результатах OCR** (`--reuse-vision`):

| Метрика | До | Повторная сборка |
|---|---:|---:|
| Не менее 4 шагов / все инструкции | ранее не измерялось | 624 / 1 036 = 60,23 % |
| Все шаги имеют неповторяющийся cropPercent / все инструкции | ранее не измерялось | 0 / 1 036 = 0 % |
| Текст шагов совпадает с документом в плане PDF, игнорируя пробелы | ранее не измерялось | 1 036 / 1 036 = 100 % |
| Автоматический PDF-чекер: без отмеченных проблем | 978 / 1 036 до прежнего фикса; 1 036 / 1 036 после | 1 036 / 1 036 |

Строгая метрика кропов требует cropPercent **на каждом шаге** и отсутствия повторений; она не
эквивалентна старому `cropUniqueShare`. Эти показатели показывают, что критерии качества задачи
**не достигнуты**. Сравнение текста проверяет план, а не полноту текста после извлечения из PDF;
спецификация, заголовки, проверки и предупреждения отдельно на полноту не измерены. Нельзя считать
это доказательством отсутствия любых обрезаний. OCR кириллицы и размеров с Recall/Precision не
измерен, русская модель и эталоны трёх архетипов пока не добавлены.

После этого прогона обнаружена и исправлена ошибка масштабирования координат RapidOCR. Данные
повторной сборки выше её не содержат: нужен полный повтор с новым OCR и его отдельный отчёт.

## Ограничения OCR — честно

1. **Кириллица не читается.** В сборке `rapidocr_onnxruntime` rec-модель — латиница/китайский.
   `ПОЗИЦИЯ` → `MO3NLNA`, `Сталь 45` → `CTab45`, `Стандарт H7` → `020H7`. Размеры и резьбы при
   этом читаются: `Ø20 H7` → `020 H7`, `M8-7H` → `M8-7H`, `Ra 1,6` → `Ra 1,6`. Кириллические
   подписи (наименование, материал, фамилии в штампе) движок не восстанавливает — сборщик честно
   ставит «уточните по штампу», а не выдумывает.
2. **Уверенность завышена.** Калибровка по 710 листам с эталонными обозначениями: доля кандидатов,
   совпавших с эталоном, растёт с `confidence` (0 % → 0 % → 6,3 % → 27,4 % для полос
   `<0,6 / 0,6–0,8 / 0,8–0,95 / ≥0,95`), но даже в верхней полосе более двух третей кандидатов не совпали с эталоном (в
   основном та самая кириллица). Порог 0,95 поэтому не «отсекает всё плохое», а только помечает
   то, что движок сам считает шатким.
3. **Мелкие веб-картинки.** На 380×280 px подписи физически в 6–8 px: даже апскейл не спасает,
   таких листов в корпусе 120 — они честно попадают в «мало что распознано».
4. **Фото.** После починки генератора (σ ≤ 0,6 вместо σ = 6) фото читаются как настоящие: 5–6
   строк на лист, среди них размеры. До этого «фото» было нечитаемым — это был баг тестового
   контура, а не движка.

## Воспроизводимость

- Корпус детерминирован по `--seed`: у каждой категории свой `random.Random(f"{seed}:{name}")`,
  поэтому правка одной категории не сдвигает остальные.
- `run_qa.py` пишет `results.jsonl` сразу после этапа vision, поэтому повторный прогон можно делать
  с `--reuse-vision` (документы и PDF собираются заново, распознавание не повторяется).
- Движок останавливается до сборки PDF: Python (до 1,4 ГБ) и Node с jsPDF вместе упирались в OOM.
  Сама сборка PDF идёт шестью процессами Node — на 290-м файле один процесс получал SIGKILL.

## Что осталось незакрытым

- **PDF, длинный текст:** длинные шаги и строки спецификации переносятся на следующие страницы;
  оставшиеся поля и реальный извлечённый текст PDF требуют отдельной полной проверки. До её
  завершения необходимо сверять инструкцию с исходным чертежом.
- **NSIS upgrade/uninstall:** шаблон удаляет перечисленные ресурсы, но не обнаружено общего удаления
  устаревших файлов каталога `engine`; фактическое обновление и удаление на Windows не проверено.

- **P3-1:** «Подготовка заготовки» и «Финальный контроль» иногда получают одинаковый фрагмент
  листа (объединение видов). В 14 из 55 документов малого прогона. Не правилось: меняет вёрстку,
  а дизайн по условию задачи трогать нельзя.
- **Windows-специфика не проверялась вживую:** нет Windows и нет `cargo`, `lib.rs` проверяется
  статически (`check:native`, 152 проверки). Пути с кириллицей, занятый порт 8000 и завершение
  движка стоит перепроверить на реальной машине после сборки `.exe`.
- **E2E в браузере** не запускался в песочнице (см. гейты): сценарии зума 40/100/250 %, пинов
  «Рентгена», подписей «Стр. 1 из N», подтверждения размера 12/18, правки шага, «Осторожно!»,
  Undo, тем, скачивания PDF и `revokeObjectURL` покрыты jsdom-тестами (`apps/studio-web/src/App.test.tsx`)
  и готовым Playwright-спеком.
